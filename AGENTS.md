## Comandos

```bash
docker compose down -v                       # apaga o volume; necessário para o init rodar de novo
docker compose up -d --wait                  # sobe o postgres e executa o init
docker compose exec postgres psql -U estacionamento -d estacionamento
docker compose run --rm testes               # só depois da Frente C
docker compose --profile apps run --rm app    # só depois da Frente C
```

- Init roda **uma única vez** na primeira subida do volume. Ordem: `01_ddl` → `02_inserts` → `procedures` → `04_indices`; `03_consultas.sql` **não** roda no init.
- `postgres-init.sh` usa `set -euo pipefail` + `ON_ERROR_STOP=1`: qualquer erro aborta a inicialização.
- Porta `${PG_PORT:-5432}`; use `PG_PORT=5433` se 5432 estiver ocupada.
- Não há `lint`/`typecheck` configurados; a verificação é subir o banco do zero e rodar a suíte JUnit.

## Regras que não podem ser quebradas

- Só PostgreSQL. Nunca sintaxe Oracle (`VARCHAR2`, `NUMBER`, `SYSDATE`, `DUAL`, `ROWNUM` etc.). FK sempre `ON DELETE RESTRICT`.
- Tipos: `VARCHAR`, `INTEGER`, `NUMERIC(10,2)`, `TIMESTAMP`, `DATE`, `BOOLEAN`, `INTEGER GENERATED BY DEFAULT AS IDENTITY` para PKs. Constraints sempre nomeadas (`pk_`, `uk_`, `fk_`, `ck_`).
- **Procedures nunca fazem `COMMIT`**; quem chama controla a transação.
- Erros de negócio com prefixo `ESTAC-00x` e SQLSTATE `P0001`; o app traduz pelo prefixo.
- Na aplicação, só bind (`?`); nunca concatenar valores. `NUMERIC` → `BigDecimal`.
- Nunca `DROP`, `TRUNCATE` ou `DELETE`/`UPDATE` sem `WHERE`; só no banco de laboratório.
- **Não edite `decisions.md`** por `edit`, `write`, `patch` ou shell. Se faltar decisão ou houver conflito, pare e pergunte ao grupo.
- Não crie tabela, coluna, consulta ou código de erro fora de `decisions.md`.
- Todo SQL só vale depois de executado; registre a saída real. Não invente tempos de performance nem resultados.
- Sem dados pessoais reais, senhas reais ou chaves no repositório.
- Não faça push; o grupo publica. Trabalho em branches `frenteX/dev`, integração por PR no `master`, Conventional Commits.

## Modelo em uma linha

7 tabelas (`tipo_veiculo`, `vaga`, `veiculo`, `tarifa`, `permanencia`, `pagamento`, `auditoria_permanencia`); N:M `veiculo` ↔ `vaga` via `permanencia`; ocupação derivada; tarifa insert-only congelada por `tarifa_id`; auditoria por trigger.
